# B2B Price Import

Модуль для **PrestaShop 8**, який імпортує ціни й активність товарів із CSV, конвертує вартість у гривні та створює фіксовані ціни для B2B-груп за матрицею знижок.

Версія модуля: `0.1.2`.

## Можливості

- завантаження CSV через адмінпанель або захищений HTTP API;
- автоматичне сканування каталогу з файлами через CLI;
- пошук товару за полем `reference`;
- розрахунок базової ціни за формулою `price × currency_rate`;
- оновлення базової ціни й активності товару;
- застосування знижок за комбінацією «категорія × бренд × група клієнтів»;
- поетапна обробка `parse` / `process` із пакетами та обмеженням часу;
- блокування паралельних запусків імпорту;
- історія імпортів, деталізація рядків і журнал аудиту;
- текстовий або JSON-вивід CLI-команди.

## Вимоги

- PrestaShop `8.0+`;
- PHP `8.1+`;
- Composer;
- доступ на запис до `modules/b2bpriceimport/var/imports`;
- налаштовані виробники, категорії та групи клієнтів у PrestaShop.

PHP-залежності описані в `composer.json`; для читання CSV використовується `league/csv`.

## Встановлення

1. Скопіюйте проєкт до каталогу модулів PrestaShop під назвою `b2bpriceimport`:

   ```text
   <prestashop-root>/modules/b2bpriceimport
   ```

2. Встановіть production-залежності:

   ```bash
   cd <prestashop-root>/modules/b2bpriceimport
   composer install --no-dev --optimize-autoloader
   ```

3. Переконайтеся, що вебсервер може створювати й змінювати файли в каталозі імпорту:

   ```text
   <prestashop-root>/modules/b2bpriceimport/var/imports
   ```

4. У бекофісі PrestaShop відкрийте **Modules → Module Manager**, знайдіть **B2B Price Import** та встановіть модуль.

Під час встановлення модуль створює службові таблиці та пункт **Catalog → B2B Price Import**. Видалення модуля видаляє його таблиці, тому перед деінсталяцією збережіть потрібну історію імпортів і журнал аудиту.

## Початкове налаштування

У меню **Catalog → B2B Price Import** доступні чотири розділи:

- **Discount Matrix** — правила знижок для категорій, брендів і груп клієнтів;
- **Configuration** — ключ API, параметри обробки, CLI та журналювання;
- **Import** — завантажені файли, запуски й результати;
- **Logs** — журнал дій модуля.

Перед першим імпортом:

1. Заповніть матрицю знижок для всіх потрібних комбінацій категорій, брендів і груп.
2. У розділі **Configuration** створіть або введіть ключ API довжиною щонайменше 32 символи.
3. За потреби змініть розмір пакета, обмеження часу, TTL блокування та параметри журналу.

## Формат CSV

CSV повинен містити заголовок і всі шість колонок:

| Колонка | Опис | Правила |
| --- | --- | --- |
| `reference` | Артикул товару в PrestaShop | обов’язковий; товар має існувати |
| `name` | Назва товару для відображення в деталях імпорту | колонка обов’язкова, значення може бути порожнім |
| `price` | Ціна у вихідній валюті | число, не менше `0` |
| `currency` | Код валюти | три латинські літери, наприклад `EUR` |
| `currency_rate` | Курс вихідної валюти до гривні | число, більше `0` |
| `active` | Активність товару | лише `0` або `1` |

Приклад із роздільником `;`:

```csv
reference;name;price;currency;currency_rate;active
SKU-001;Папір офісний A4;10.50;EUR;48.20;1
SKU-002;Папка-реєстратор;125.00;UAH;1;1
```

Модуль автоматично визначає роздільник `;` або `,`. Для десяткових значень приймаються крапка й кома; якщо кома одночасно є роздільником CSV, десяткове значення потрібно правильно взяти в лапки за правилами CSV.

Ціна, яка записується в PrestaShop:

```text
price_uah = round(price × currency_rate, 6)
```

Поле `currency` перевіряється та зберігається в історії, але модуль не отримує курс автоматично. Значення `currency_rate` має вже містити потрібний курс до гривні.

## Як обробляється товар

Для кожного валідного рядка модуль:

1. знаходить товар за `reference`;
2. обчислює базову ціну в UAH;
3. знаходить активні правила матриці для бренду й категорій товару;
4. розраховує фіксовану ціну кожної B2B-групи:

   ```text
   group_price = base_price × (1 − discount_percent / 100)
   ```

5. замінює відповідні групові записи `specific_price`;
6. оновлює базову ціну та поле `active` товару.

Якщо товар не має виробника, категорії або відповідного активного правила матриці знижок, обробка цього рядка завершиться помилкою. Помилка одного рядка не скасовує вже успішно оброблені рядки.

> Модуль записує обчислене значення без додаткової податкової конвертації. Формат вихідної ціни має відповідати правилам ціноутворення конкретного магазину.

## Імпорт через адмінпанель

1. Відкрийте **Catalog → B2B Price Import → Import**.
2. Завантажте файл `.csv`.
3. Запустіть обробку збереженого файлу.
4. Відкрийте деталі імпорту, щоб переглянути статуси, знайдені товари й помилки окремих рядків.

Завантаження лише зберігає файл. Сам імпорт запускається окремою дією. Видалення запису історії не видаляє CSV, а видалення CSV не видаляє пов’язану історію.

## HTTP API

API призначений, зокрема, для інтеграції з 1С. Рекомендовано передавати секрет у заголовку `X-B2B-Import-Key`, щоб він не потрапляв до URL і журналів вебсервера.

### 1. Завантажити CSV

```bash
curl --request POST \
  --header "X-B2B-Import-Key: <access-key>" \
  --form "file=@/path/to/prices.csv" \
  "https://shop.example/module/b2bpriceimport/upload"
```

Успішна відповідь має HTTP-статус `201` і повертає `file.stored_filename`:

```json
{
  "success": true,
  "error_code": null,
  "file": {
    "original_filename": "prices.csv",
    "stored_filename": "20260821_120000_a1b2c3d4e5f60708.csv",
    "size": 1024,
    "sha256": "..."
  },
  "message": "CSV file uploaded. The import was not started."
}
```

### 2. Запустити конкретний завантажений файл

```bash
curl --request POST \
  --header "X-B2B-Import-Key: <access-key>" \
  --data-urlencode "file=<stored_filename>" \
  "https://shop.example/module/b2bpriceimport/import"
```

Щоб запустити автоматичне сканування каталогу без вибору конкретного файлу, не передавайте параметр `file`:

```bash
curl --request POST \
  --header "X-B2B-Import-Key: <access-key>" \
  "https://shop.example/module/b2bpriceimport/import"
```

Ключ також можна передати як `?key=<access-key>`, але заголовок безпечніший. Endpoint запуску приймає `GET` і `POST`; для операції, що змінює дані, рекомендовано використовувати `POST`.

Основні HTTP-статуси:

| Статус | Значення |
| --- | --- |
| `200` | запуск завершено |
| `201` | CSV завантажено |
| `400` | некоректний файл або параметри |
| `401` | неправильний ключ API |
| `405` | HTTP-метод не підтримується |
| `409` | інший імпорт уже виконується |
| `413` | файл перевищує PHP-ліміт завантаження |
| `500` | помилка імпорту |

Готова колекція для тестування: [`docs/B2B-Price-Import.postman_collection.json`](docs/B2B-Price-Import.postman_collection.json).

Перед використанням колекції замініть `base_url` і `access_key` власними значеннями.

## CLI

Команду потрібно запускати з кореня PrestaShop:

```bash
php bin/console b2b:price-import:run --env=prod --no-debug
```

Без `--import-id` команда сканує каталог `modules/b2bpriceimport/var/imports`, реєструє новий CSV і запускає його відповідно до налаштувань. Файли з уже зареєстрованим SHA-256 не імпортуються повторно.

Приклади:

```bash
# Обробити конкретний запис імпорту
php bin/console b2b:price-import:run --import-id=42 --type=all --env=prod --no-debug

# Вибрати конкретний файл у каталозі сканування
php bin/console b2b:price-import:run --file=prices.csv --format=json --env=prod --no-debug

# Лише розібрати CSV
php bin/console b2b:price-import:run --import-id=42 --type=parse --env=prod --no-debug

# Обробити вже розібрані рядки
php bin/console b2b:price-import:run --import-id=42 --type=process --limit=1000 --env=prod --no-debug
```

Доступні опції:

| Опція | Призначення |
| --- | --- |
| `--import-id=ID` | обробити наявний запис імпорту |
| `--file=FILE.csv` | вибрати конкретний файл із каталогу сканування |
| `--type=parse\|process\|all` | вибрати етап виконання |
| `--limit=N` | кількість рядків у пакеті, `1–5000` |
| `--time-limit=N` | максимальний час запуску, `1–3600` секунд |
| `--lock-ttl=N` | TTL блокування, `1–3600` секунд |
| `--force` | примусово замінити поточне блокування |
| `--format=text\|json` | формат результату |
| `--scan-dir=PATH` | перевизначити каталог сканування |
| `--max-file-age-hours=N` | максимальний вік нового файлу, `1–168` годин |
| `--scan-limit=N` | кількість файлів для реєстрації за запуск, `1–50` |

Повна довідка:

```bash
php bin/console b2b:price-import:run --help
```

### Приклад cron

Запуск щохвилини:

```cron
* * * * * cd /var/www/prestashop && /usr/bin/php bin/console b2b:price-import:run --env=prod --no-debug >> var/log/b2b-price-import.log 2>&1
```

Вкажіть реальні шляхи до PrestaShop і PHP. Вбудоване блокування не дозволяє двом імпортам виконуватися одночасно.

## Основні налаштування

| Налаштування | Типове значення | Діапазон / варіанти |
| --- | ---: | --- |
| Тип запуску | `all` | `parse`, `process`, `all` |
| Розмір пакета | `500` | `1–5000` |
| Обмеження часу CLI | `55` с | `1–3600` |
| TTL блокування | `120` с | `1–3600` |
| Максимальний вік файлу | `24` год | `1–168` |
| Ліміт сканування | `1` | `1–50` |
| Формат CLI | `text` | `text`, `json` |
| Зберігання логів | `180` днів | `0–3650`; `0` — безстроково |

Журналювання можна фільтрувати за типом сутності та результатом. Для товарів доступний стислий режим на весь імпорт або детальний запис кожної зміни. Секрети редагуються перед записом у журнал.

## Службові таблиці

З урахуванням префікса бази PrestaShop модуль створює:

- `b2b_discount_rule` — матриця знижок;
- `b2b_import` — запуски імпорту;
- `b2b_import_job` — етапи імпорту;
- `b2b_import_item` — вихідні рядки та їхні статуси;
- `b2b_import_price_staging` — нормалізовані ціни перед обробкою;
- `b2b_import_lock` — блокування паралельного запуску;
- `b2b_audit_log` — журнал аудиту.

## Типові проблеми

### `Product not found by reference`

Перевірте, що `reference` у CSV точно збігається з артикулом товару в PrestaShop.

### `No active discount rule found...`

Додайте активне правило в **Discount Matrix** для категорії, бренду й потрібної групи. Також перевірте, що товар має виробника та хоча б одну категорію.

### `Another price import is already running`

Дочекайтеся завершення іншого запуску. `--force` використовуйте лише після перевірки, що попередній процес справді більше не працює.

### Файл не знаходиться сканером

Перевірте розширення `.csv`, права читання, каталог сканування та вік файлу. За замовчуванням файли старші за 24 години пропускаються.

### Завантаження відхиляється через розмір

Перевірте PHP-параметри `upload_max_filesize` і `post_max_size` для вебпроцесу.

## Безпека й експлуатація

- використовуйте HTTPS для API;
- зберігайте API-ключ у секретному сховищі та регулярно змінюйте його;
- передавайте ключ у `X-B2B-Import-Key`, а не в URL;
- не робіть `var/imports` публічним: у комплекті є `.htaccess`, який забороняє HTTP-доступ;
- перед масовим імпортом створіть резервну копію бази даних;
- у multistore-середовищі спочатку перевірте імпорт на тестовому товарі: базова ціна оновлюється в записах `product` і `product_shop`, а групова ціна створюється для поточного контексту магазину.
